# 设计原则

产品边界与 UI 原则统一维护在 [产品规格](../PROJECT_SPEC.md) 的第 2、6、12、13 节，本文件作为设计入口，不另行复制规则。

修改 UI 时核对：
- 用户目标与中文文案是否明确。
- 常用操作是否容易找到，交互是否增加不必要的步骤。
- 手机和平板布局是否在本次涉及的设备上验证。
- 服务卡片交互见 [卡片验证](widget-technical-validation.md)。

## 时间线原型如何试用

以下是候选原则与试用示例，具体任务随原型确定。

| 候选原则 | 在时间线上怎么观察 | 可复用的场景 |
| --- | --- | --- |
| 浏览时，用户能直接读到当前任务所需的信息 | 给定当前日期和时刻，请试用者指出下一项有明确时刻的安排。记录答对人数、用时和漏看的信息。 | 卡片首屏读取主要信息 |
| 高频操作有可识别的直接入口 | 请试用者打开指定事项，记录首次点击位置、总点击数和误触。原型可先试点整行进入详情。 | 首页事项行、搜索结果 |
| 重要状态同时有文字或形状提示 | 把同一屏切成灰度，请试用者区分选中日期与其他日期，记录错认的位置。 | 日期选择、筛选选中态 |

用今天和明天各 3 件事项的样例试色，今天共占 2 小时，明天共占 4 小时。请试用者指出哪天安排更满，再读出明天学习事项的名称和时段并点开它，观察较弱的前景是否影响阅读或点击。在两列相同的时段各放一张工作便签，检查中线对齐和跨日色相；在空档处单独核对忙闲底色。学习、工作、生活是试色用的示例，原生时间线用标签色对应日期圈和便签。

比较两版时使用相同数据、设备和任务，交替体验顺序。原型评审可以直接展示“3 人中 2 人第一次点对，另 1 人点了时间”，让团队根据误触位置决定下一处改动。此处人数仅为记录格式示例。
