# 信息模块

信息模块描述事项需要哪些记录能力，不把事项分类成任务、项目或习惯。用户在创建事项的同一页面选择信息类型，已创建事项仍可在详情页修改。

## V1 模块

| 用户可见名称 | 用途 | V1 行为 |
| --- | --- | --- |
| 记录 | 记录某件事发生的时刻 | 点击「记录一次」生成时间记录 |
| 计数 | 累加数值或每日一次 | 支持 `+1`、`+10`、自定义数值、今日一次 |
| 截止日期 | 保存关键日期 | 使用快捷日期或原生日期选择器，可填地点 |
| 备注 | 自由文本 | 保存可持续修改的说明 |
| 列表 | 文字项和事项引用 | 支持完成状态、打开独立关联事项 |

选择了「截止日期」后，系统自动生成倒计时展示。倒计时是派生显示，不作为用户需要单独选择或编辑的模块。

## 列表与关联事项

列表既可以放普通文字项，也可以放独立事项引用。例如“本学期要做的事”可以关联“六级考试”和“雅思考试”，每个考试仍然拥有自己的截止日期和倒计时。

V1 只允许一层关联：关联事项不能再拥有自己的事项列表。关联不是所有权关系，删除列表项只解除关联，删除主事项也不会删除被关联事项；被关联事项可独立出现在首页和卡片中。

## 明确不做

- 不把进度作为用户可选模块；旧数据和接口仅保留兼容读取。
- 不做多级项目树、父子事项或自动级联删除。
- 不做公式引擎。
- 不做传统标签和分类。

## 配置策略

每个模块实例保存 `configJson`。V1 用简单 JSON 支持快速迭代；当某类模块稳定后，再拆出专用存储结构。
